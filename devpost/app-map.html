Acorn App Map

A weekly rewards app: clear missions to earn acorns, then trade the acorns you saved for rewards.

The Big Picture

  • Screens (mobile/src/app/): home, rewards, settings, and the weekly setup flow.
  • Game rules (mobile/src/domain/): balance, progress steps, the undo deadline, the week switch, and more. Pure functions that do not depend on the screens, checked with unit tests.
  • Saving (mobile/src/storage/): every change goes through reduce(data, action, now) and is saved to acorn:v1 on the device.
  • API server (api/): has Jev judge mission difficulty and reward price ranges, and converts them into numbers of acorns.

The Flow of One Action: Clearing a Mission

Reference Route (3 Stops)

This is not a route we walked through together, but a reference route to read later. Search for the symbol names to find each spot in its file.

  1. mobile/src/app/index.tsx › function record
    Called from the save button in the record window and from the check button. Dispatches recordProgress, and when the target is reached, starts the card effect and the acorns flying to the top right (launchPoints).
  2. mobile/src/storage/reducer.ts › case 'recordProgress'
    Saves the progress, and the moment the target is reached, creates the clear record (Clear). For undo, it also keeps the progress from before the clear (progressBefore). Tests are in mobile/src/storage/__tests__/reducer.test.ts.
  3. mobile/src/domain/balance.ts › export function balance
    Acorns on hand = total acorns from clears − total acorns of redeemed rewards. The top right of both the home screen and the rewards screen shows this value. The check for whether a reward can be redeemed (rewards.ts › canRedeem) also uses it.

To Change This, Start Here

  • Screen text: mobile/src/i18n/ja.ts and en.ts. If a key is missing from either one, the type check fails.
  • Recording steps (1, 5, 10, 10%): mobile/src/domain/progress.ts › progressStep.
  • Reward price multiplier (1.3x): api/src/acorn_api/pricing.py › REWARD_MARKUP. After changing it, rebuild the API container.
  • Number of acorns for missions: mission_pt in the same file.
  • Tabs: mobile/src/ui/NavBar.tsx › TABS. The icons' pixel art is in mobile/src/ui/PixelIcon.tsx › ICONS.
  • Undo deadline (30 minutes): mobile/src/domain/clears.ts › UNDO_MS.

A Practice You Can Reuse Elsewhere

When removing an explanatory label from a display, go back to the record of what that number was decided to mean and check it.

The top right of the home screen was decided to be "Total earned (does not go down when redeeming)," and later the "Total earned" label was removed for looks. The calculation was correct, and the totalEarned tests passed. Even so, when actually redeeming during the final review, it felt like "it didn't go down when I went back to the home screen." So the display was changed to acorns on hand (balance) (devpost/checklist.md › Revisions, devpost/prd.md › Screens and Layout).

Tests can check "does it calculate as decided," but not "does that decision come across to the person using it." Even for a visual change, check in the PRD whether an earlier decision relied on the explanatory label, and confirm by actually using the app. This works in other projects too.
