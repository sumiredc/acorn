Acorn アプリマップ

ミッションをクリアしてどんぐりを稼ぎ、ためたどんぐりをごほうびと交換する、週ごとのごほうびアプリ。

全体像

  • 画面（mobile/src/app/）：ホーム・ごほうび・設定・週の準備フロー。
  • ゲームのルール（mobile/src/domain/）：残高、進み具合の刻み、取り消しの期限、週の切り替えなど。画面に依存しない純粋な関数で、ユニットテストで確かめている。
  • 保存（mobile/src/storage/）：すべての変更は reduce(data, action, now) を通り、端末の acorn:v1 に保存される。
  • API サーバー（api/）：Jev にミッションの難しさと報酬の価格帯を判定させ、どんぐりの数に換算する。

1 つの操作の流れ：ミッションをクリアする

参考ルート（3 か所）

一緒にたどったルートではなく、あとから読むための参考ルートです。ファイル内は記号名で検索すると見つかります。

  1. mobile/src/app/index.tsx › function record
    記録の窓の保存やチェックのボタンから呼ばれる。recordProgress を dispatch し、目標に届いたらカードの演出と、どんぐりが右上へ飛ぶ動き（launchPoints）を始める。
  2. mobile/src/storage/reducer.ts › case 'recordProgress'
    進み具合を保存し、目標に届いた瞬間にクリアの記録（Clear）を作る。取り消し用に、クリア前の進み具合（progressBefore）も残す。テストは mobile/src/storage/__tests__/reducer.test.ts。
  3. mobile/src/domain/balance.ts › export function balance
    手持ち = クリアのどんぐりの合計 − 交換したごほうびのどんぐりの合計。ホームとごほうび画面の右上は、どちらもこの値を出す。交換できるかの判定（rewards.ts › canRedeem）もこれを使う。

ここを変えたいときは、ここから

  • 画面の文言：mobile/src/i18n/ja.ts と en.ts。キーが片方に欠けると型チェックで落ちる。
  • 記録の刻み（1・5・10、10%）：mobile/src/domain/progress.ts › progressStep。
  • ごほうびの値段の倍率（1.3 倍）：api/src/acorn_api/pricing.py › REWARD_MARKUP。変えたら API のコンテナを作り直す。
  • ミッションのどんぐりの数：同じファイルの mission_pt。
  • タブ：mobile/src/ui/NavBar.tsx › TABS。アイコンのドット絵は mobile/src/ui/PixelIcon.tsx › ICONS。
  • 取り消しの期限（30 分）：mobile/src/domain/clears.ts › UNDO_MS。

ほかでも使える進め方

表示から説明の文字を外すときは、その数が何を表していたかを決めた記録まで戻って確かめる。

ホームの右上は「累計（交換しても減らない）」と決め、あとで見た目のために「累計」の文字を外した。計算は正しく、totalEarned のテストも通っていた。それでも最終確認で実際に交換してみると「ホームに戻っても減っていない」と感じられた。そこで手持ち（balance）の表示に変えた（devpost/checklist.md › Revisions、devpost/prd.md › ホーム）。

テストは「決めたとおりに計算しているか」は確かめられるが、「その決めごとが使う人に伝わるか」は確かめられない。見た目の変更でも、前の決定が説明の文字に頼っていなかったかを PRD で確かめ、実際に操作して確認する。これは別のプロジェクトでも使える。

もう一度動かす

docker compose up --build        # リポジトリの一番上で：API サーバー → http://localhost:8000
cd mobile && npx expo start --web  # アプリ → http://localhost:8081
cd mobile && npm test             # ユニットテスト
